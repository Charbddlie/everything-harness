# 简单文档
这是写文档与注释的原则，以下将“文档与注释”称为“内容”。

当项目级不存在文档与注释的约定时，遵循以下原则：
+ 删除内容时，需要彻底删除，让对应内容仿佛从来没有存在过
+ 创建新内容时
   + 只有内容不写会导致后续一定会出现重复错误时，才写
   + 只写最简单结论，除非文件定位是交互历史，否则不要写试错历史，比如之前尝试过xx
   + 禁止负向描述，先肯定后否定，如：是通过python代码，**而不是ai生成**；只写文件，**不读取**。
+ 更新内容时，需要对现有文档做清理
   + 当内容不再约束现在的代码或流程，删除
   + 当代码或流程已经固定，错误做法不会回退了，删除
